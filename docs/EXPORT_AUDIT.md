# Rawafed export and print audit

This inventory documents the active export paths after final stabilization. It does not change posted records or historical document snapshots.

## Invoices

- Invoice template, invoice detail, and invoice-generation downloads all use `InvoicePdfService`.
- The service draws text, lines, totals, and tables as vector PDF content. The Rawafed logo and ZATCA QR remain raster images by design.
- The PDF contains searchable invoice identifiers and numeric totals, embeds the static Amiri Arabic font, uses A4 dimensions, wraps long line descriptions, and paginates line items.
- Invoice Print builds and opens the same invoice PDF document used by Download PDF. It no longer invokes browser printing on the application page.

## Accounting and operational reports

- Finance reports and account-ledger PDF downloads use `ReportExportService`.
- Report tables are rendered as vector text and rules with static Amiri Arabic font embedding, content-aware column widths, wrapped variable-height rows, repeated headers, page numbers, and page breaks.
- Reports include the Rawafed logo and navy/red identity. When a report response supplies chart data, the PDF renders a vector chart above its table.
- The Reports Print action opens the generated PDF and prints that document instead of printing the ERP shell.
- Excel exports use typed worksheet cells rather than screenshots. Monetary values remain numeric so totals and filters work in spreadsheet software.
- Chart of Accounts ledger export uses the same backend ledger response as the on-screen drawer.

## Admission documents

- Registration contract, student information file, and admission letter use jsPDF/pdf-lib text drawing. Contract field values are shaped before pdf-lib draws them, preventing detached Arabic glyphs.
- The student information file embeds Amiri and draws its business text as vector PDF text; it no longer converts each text field to a canvas image.
- Signatures, QR codes, logos, and approved stationery artwork are embedded images; form text is not converted to a page screenshot.
- A completed submission remains available on the success step for explicit PDF download. Starting a new registration is a separate user action.

## Print targets

- Payment receipts, student statements, expense registers, inventory registers, fixed-asset reports, finance reports, trial balance, and invoice detail actions now build and print the PDF document itself.
- The public registration review Print action builds the registration-information PDF rather than printing the registration application shell.
- No active application component calls `window.print()` directly. The only print invocation is owned by a generated PDF window after its blob has loaded.
- Payroll does not currently expose a report-print action; adding a payroll PDF template remains a separate product capability rather than a browser-print fallback.

## Verification contract

- `backend/tests/report-export.behavior.test.ts` verifies multiple pages, searchable vector invoice/report content, Arabic extraction through Amiri, and numeric totals.
- No application source imports or calls `html2canvas`.
- Images are limited to visual assets that cannot remain text (logo, QR, signatures, stationery).

## Spreadsheet status

- Finance report workbooks generated by `ReportExportService` are native `.xlsx` with typed date/currency/number cells, useful widths, Arabic text, and a checks sheet.
- Trial Balance, Chart of Accounts, account-ledger, and fixed-asset report buttons now use the same native `.xlsx` generator instead of renaming UTF-8 CSV files as Excel exports.
- The Chart of Accounts import template intentionally remains CSV because it is a machine-import contract rather than a presentation report.
